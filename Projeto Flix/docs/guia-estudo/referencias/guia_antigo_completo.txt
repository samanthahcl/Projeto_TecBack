1. O QUE É O PROJETO IESPFLIX?
Objetivo Geral
O IESPFLIX é uma API REST (uma interface de comunicação entre sistemas via internet) que simula o
backend de um serviço de streaming, parecido com Netflix. Você está construindo o lado servidor da
aplicação — a parte que recebe pedidos, processa, consulta o banco de dados e devolve respostas.
O que é uma API REST?
REST significa Representational State Transfer. É um padrão de como sistemas conversam pela internet.
Quando você acessa um app e ele mostra filmes, por baixo ele está chamando uma API REST que busca
esses dados no banco de dados. Essa API é o que você construiu!

4. ENTIDADES (MODELS) — AS TABELAS DO BANCO DE DADOS
EM JAVA
As entidades são classes Java que representam tabelas do banco de dados. O Hibernate (que é o JPA
por baixo) lê essas classes e cria as tabelas automaticamente. Cada atributo da classe vira uma coluna
na tabela.
Anotações Essenciais das Entidades
Anotação
O que significa?
@Entity
Diz ao Hibernate que esta classe é uma tabela do banco
@Table(name = "filmes")
Define o nome da tabela no banco (opcional, padrão é o nome da classe)
@Id
Define o campo como chave primária (PK) da tabela
@GeneratedValue(strategy = GenerationType.IDENTITY)
O banco gera o ID automaticamente (auto-increment)
@Column(nullable = false, length = 100)
Configura a coluna: não pode ser nula, máximo 100 caracteres
@Column(unique = true)
O valor deste campo deve ser único na tabela (como email)
@Column(columnDefinition = "TEXT")
Campo de texto longo (sem limite fixo de caracteres)
@Data (Lombok)
Gera automaticamente: getters, setters, toString, equals, hashCode
@Builder (Lombok)
Permite criar objetos com padrão builder: Filme.builder().titulo(...).build()
@NoArgsConstructor (Lombok)
Gera construtor sem argumentos (exigido pelo JPA)
@AllArgsConstructor (Lombok)
Gera construtor com todos os argumentos
Exemplo Completo: Filme.java
Veja como cada parte do código se conecta com o banco:

5. DTOs — POR QUE NÃO EXPOR A ENTIDADE DIRETAMENTE?
DTO significa Data Transfer Object (Objeto de Transferência de Dados). São classes simples usadas
para receber dados da requisição e enviar dados na resposta da API.
Por que usar DTOs em vez da entidade diretamente?
■ Segurança: Você controla quais campos são expostos. Ex.: nunca expor senha_hash na resposta.
■ Validação: As anotações de validação (@NotBlank, @Email) ficam no DTO, não na entidade.
■ Flexibilidade: O DTO pode ter campos diferentes da entidade (combinar dados de várias tabelas).
■ Desacoplamento: Mudanças no banco de dados não afetam diretamente o contrato da API.
Exemplo: FilmeDTO.java
@Data // Lombok: getters/setters @Builder // Lombok: builder pattern @NoArgsConstructor //
Lombok: construtor vazio @AllArgsConstructor// Lombok: construtor completo public class
FilmeDTO { private Long id; @NotBlank(message = "O titulo e obrigatorio") // Validacao:
campo nao pode ser vazio private String titulo; private String sinopse; private LocalDate
dataLancamento; private String genero; private Integer duracaoMinutos; private String
classificacaoIndicativa; }

6. MAPPERS — CONVERTENDO ENTRE ENTIDADE E DTO
O Mapper é uma classe responsável por converter dados entre a Entidade (que vem do banco) e o DTO
(que vai para a API e volta dela). É como um tradutor.
Como funciona o FilmeMapper?
@Component // Spring gerencia esta classe (pode ser injetada em outras) public class
FilmeMapper { private final ModelMapper modelMapper; // Biblioteca que copia campos
automaticamente // Converte DTO -> Entidade (usado ao receber dados da API para salvar no
banco) public Filme toEntity(FilmeDTO dto) { if (dto == null) return null; return
modelMapper.map(dto, Filme.class); } // Converte Entidade -> DTO (usado ao buscar do banco
para enviar para o cliente) public FilmeDTO toDTO(Filme entity) { if (entity == null)
return null; return modelMapper.map(entity, FilmeDTO.class); } }
Mappers Manuais vs. ModelMapper
O projeto usa dois estilos de mapper:
 FilmeMapper: usa ModelMapper (copia campos automaticamente pelo nome).
 ClienteMapper, PedidoMapper, etc.: mapeamento manual com builder do Lombok — você
especifica campo a campo:
// Mapper manual (ClienteMapper) public Cliente toEntity(ClienteDTO dto) { return
Cliente.builder() .id(dto.getId()) .nome(dto.getNome()) .cpf(dto.getCpf())
.telefone(dto.getTelefone()) .endereco(dto.getEndereco()) .build(); }

7. REPOSITORIES — ACESSO AO BANCO DE DADOS
O Repository é a camada que conversa com o banco de dados. Ao extender JpaRepository, você
ganha dezenas de métodos prontos GRATUITAMENTE, sem precisar escrever SQL.
Métodos Gratuitos do JpaRepository
Método Pronto
O que faz
findAll()
SELECT * FROM filmes
findById(id)
SELECT * FROM filmes WHERE id = ?
save(entity)
INSERT ou UPDATE (se já tem id)
deleteById(id)
DELETE FROM filmes WHERE id = ?
existsById(id)
Retorna true se existe um registro com esse id
count()
SELECT COUNT(*) FROM filmes
O FilmeRepository — Com JPQL (Requisito do Professor!)
JPQL (Java Persistence Query Language) é uma linguagem de consulta parecida com SQL, mas que
opera sobre objetos Java em vez de tabelas. O professor exige 4 consultas JPQL. Veja as que foram
implementadas:
@Repository public interface FilmeRepository extends JpaRepository { // JPQL 1: Lista
filmes ordenados por titulo (A-Z) // "f" e o alias para Filme, "f.titulo" e o campo Java
(nao coluna do banco) @Query("select f from Filme f order by f.titulo asc") List
listarFilmesOrdenados(); // Query Method (Spring Data): Spring gera o SQL automaticamente
pelo nome do metodo! // Equivale a: SELECT * FROM filmes ORDER BY titulo ASC List
findAllByOrderByTituloAsc(); // Derived Query: busca por genero E titulo ao mesmo tempo
Optional findByGeneroAndTitulo(String genero, String titulo); // JPQL com parametros
nomeados (@Param) // :genero e :titulo sao substituidos pelos valores passados no metodo
@Query("select f from Filme f where f.genero = :genero and f.titulo = :titulo") Filme
buscarPorGenero(@Param("genero") String gen, @Param("titulo") String tit); }
■ Importante: Em JPQL você escreve o nome da classe Java (Filme) e seus atributos Java (titulo,
genero), NÃO os nomes das colunas do banco (filmes, titulo). O Hibernate faz a tradução.

8. SERVICES — A LÓGICA DE NEGÓCIO DA APLICAÇÃO
O Service contém as regras de negócio da aplicação. É aqui que fica toda a lógica: validar dados, tratar
erros, chamar o repository, etc. O Controller apenas repassa o pedido para o Service.
Estrutura do FilmeService
@Service // Marca como componente de servico do Spring @Slf4j // Lombok: cria logger
automaticamente (log.info(), log.error(), etc.) @RequiredArgsConstructor // Lombok: gera
construtor com todos os campos final (injecao de dependencia) public class FilmeService {
private final FilmeRepository filmeRepository; // Injeta o repository private final
FilmeMapper filmeMapper; // Injeta o mapper // Metodo listar: busca todos os filmes e
converte para DTO public List listar() { log.info("Buscando todos os filmes cadastrados");
// Log de inicio da operacao List filmes = filmeRepository.findAll(); // Busca no banco
return filmes.stream() .map(filmeMapper::toDTO) // Converte cada Filme para FilmeDTO
.collect(Collectors.toList()); } // Metodo buscarPorId: busca um filme ou lanca excecao se
nao existir public FilmeDTO buscarPorId(Long id) { log.info("Buscando filme pelo ID: {}",
id); Filme filme = filmeRepository.findById(id) .orElseThrow(() -> { // Se nao encontrar,
lanca RuntimeException com mensagem return new RuntimeException("Filme nao encontrado com
o ID: " + id); }); return filmeMapper.toDTO(filme); } // Metodo salvar: recebe DTO,
converte para entidade, salva no banco @Transactional // Garante que toda a operacao e
atomica (tudo ou nada) public FilmeDTO salvar(FilmeDTO filmeDTO) { log.info("Salvando novo
filme: {}", filmeDTO.getTitulo()); Filme filme = filmeMapper.toEntity(filmeDTO); // DTO ->
Entidade Filme filmeSalvo = filmeRepository.save(filme);// Salva no banco return
filmeMapper.toDTO(filmeSalvo); // Entidade -> DTO para retornar } }
Por que @Transactional?
A anotação @Transactional garante que se algo der errado durante a operação, o banco de dados é
revertido ao estado anterior (rollback). É como uma 'transação bancária': ou tudo acontece, ou nada
acontece.
O FuncionarioService — Integração com ViaCEP
@Service @RequiredArgsConstructor public class FuncionarioService { private final

O Custom Validator @Genero — Passo a Passo
Um Custom Validator tem SEMPRE duas partes: a anotação e o validador.
PARTE 1 — A anotação (Genero.java):
@Documented // Aparece no Javadoc @Constraint(validatedBy = GeneroValidator.class) // Qual
classe faz a validacao? @Target({ElementType.FIELD, ElementType.PARAMETER}) // Onde pode
ser usada? @Retention(RetentionPolicy.RUNTIME) // Disponivel em tempo de execucao public
@interface Genero { String message() default "Genero invalido"; // Mensagem padrao de erro
Class[] groups() default {}; Class[] payload() default {}; }
PARTE 2 — A lógica (GeneroValidator.java):
public class GeneroValidator implements ConstraintValidator { // Lista de generos aceitos

"Animacao", "Musical", "Suspense", "Fantasia", "Thriller", "Crime", "Biografia", "Guerra",
"Historia", "Faroeste", "Familia", "Esporte" ); @Override public boolean isValid(String
genero, ConstraintValidatorContext context) { // Se o campo for nulo ou vazio, deixa
passar (outros validators cuidam disso) if (genero == null || genero.isBlank()) { return
true; } // Retorna true se o genero informado esta na lista, false caso contrario return
GENEROS_VALIDOS.contains(genero.trim()); } }

11. TRATAMENTO GLOBAL DE ERROS — GlobalExceptionHandler
Em vez de tratar erros em cada Controller separadamente, o projeto usa um handler global que captura
exceções de qualquer Controller e retorna respostas padronizadas no formato JSON.
Como funciona o GlobalExceptionHandler.java?
@RestControllerAdvice // Intercepta excecoes de TODOS os controllers public class
GlobalExceptionHandler { // Captura erros de validacao (quando @Valid falha)
@ExceptionHandler(MethodArgumentNotValidException.class) public ResponseEntity>
handleValidationException( MethodArgumentNotValidException ex, HttpServletRequest request)
{ Map body = new LinkedHashMap<>(); body.put("timestamp", LocalDateTime.now());
body.put("status", 400); body.put("error", "Bad Request"); body.put("message", "Dados
invalidos na requisicao"); body.put("path", request.getRequestURI()); // Coleta todos os
erros de campo Map fieldErrors = new HashMap<>();
ex.getBindingResult().getAllErrors().forEach(error -> { String fieldName = ((FieldError)
error).getField(); String errorMessage = error.getDefaultMessage();

12. INTEGRAÇÃO COM API EXTERNA — OpenFeign e ViaCEP
O projeto consome a API ViaCEP (viacep.com.br) para buscar dados de endereço a partir do CEP. Isso é
feito usando o OpenFeign, uma biblioteca que cria clientes HTTP de forma declarativa (você só declara a
interface, o Feign faz o resto).
ViaCepClient.java — O Cliente Feign
@FeignClient( name = "viaCepClient", url = "${viacep.url:https://viacep.com.br/ws}" // URL
vem do application.properties ) public interface ViaCepClient { // Faz GET para:
https://viacep.com.br/ws/{cep}/json/ // Retorna os dados mapeados no ViaCepResponseDTO
@GetMapping("/{cep}/json/") ViaCepResponseDTO buscarPorCep(@PathVariable("cep") String
cep); }
ViaCepResponseDTO.java — Os Dados que Voltam
@Data public class ViaCepResponseDTO { private String cep; // Ex: "58000-000" private
String logradouro; // Ex: "Avenida Epitacio Pessoa" private String bairro; // Ex: "Centro"

@JsonProperty("erro") // Campo "erro" do JSON -> atributo erro da classe private Boolean
erro; // true se o CEP nao existir }

16. COMO EXPLICAR NA APRESENTAÇÃO — ROTEIRO E FRASES
Use este roteiro como guia. Fale com confiança — você fez esse projeto!
Introdução (1-2 minutos)
"O projeto IESPFLIX é uma API REST desenvolvida com Spring Boot 3. Ela simula o backend de um
serviço de streaming, onde é possível gerenciar filmes, usuários, funcionários e outras entidades. Toda a
comunicação é feita através de requisições HTTP com respostas em JSON."
Explicando a Arquitetura (2-3 minutos)
"O projeto segue a arquitetura em camadas. Quando uma requisição chega, ela passa pelo Controller,
que valida os dados e chama o Service. O Service contém a lógica de negócio e chama o Repository, que
acessa o banco de dados H2. Os dados retornam como DTOs, não como entidades diretamente, para
proteger informações sensíveis e ter controle sobre o que é exposto."
Explicando o Custom Validator (1-2 minutos)
"Um dos requisitos era criar um Custom Validator. Implementei o @Genero, que é uma anotação
customizada usada no campo gênero da entidade Filme. O GeneroValidator verifica se o gênero
informado está em uma lista pré-definida de gêneros válidos. Se não estiver, o Spring automaticamente
retorna um erro 400 Bad Request com a mensagem de erro."
Explicando as Queries JPQL (1-2 minutos)
"Para as consultas JPQL, implementei no FilmeRepository. JPQL é como SQL, mas opera sobre os
objetos Java. Por exemplo, listarFilmesOrdenados() usa JPQL para trazer todos os filmes ordenados
alfabeticamente pelo título. Também implementei busca por gênero com parâmetros nomeados."
Explicando a Integração Externa (1-2 minutos)
"O projeto integra com a API ViaCEP usando OpenFeign. Quando cadastro um funcionário com CEP, o
sistema automaticamente consulta a API e preenche logradouro, bairro, cidade e estado. Se o CEP for
inválido, o ViaCEP retorna erro=true e lançamos uma CustomBeanException, que é capturada pelo
GlobalExceptionHandler e retorna uma resposta de erro formatada."
Explicando os Testes (1-2 minutos)
"O projeto possui testes em três camadas. Nos testes de Controller, uso MockMvc para simular
requisições HTTP sem subir o servidor. Nos testes de Service, uso Mockito para criar mocks do
Repository e do Mapper, testando apenas a lógica. Nos testes de Repository, uso @DataJpaTest com
banco H2 em memória para testar as queries reais. A cobertura está acima de 80%."
Perguntas Frequentes na Apresentação
■ Por que usar DTO e não a entidade diretamente?
■ Para ter controle sobre o que é exposto na API, separar validações da persistência e evitar expor dados
sensíveis como senha.
■ O que é @Transactional?
■ Garante que uma operação seja atômica: se algo falhar no meio, o banco reverte tudo ao estado
anterior.

■ O que é Lombok?
■ Uma biblioteca que gera código repetitivo (getters, setters, construtores, toString) automaticamente em
tempo de compilação. Reduz boilerplate.
■ O que é Swagger?
■ Uma ferramenta de documentação automática. O SpringDoc OpenAPI lê as anotações do código e
gera uma interface visual em /swagger-ui.html para testar a API.
■ Por que H2 e não PostgreSQL?
■ H2 é um banco em memória, ideal para desenvolvimento porque não precisa instalar nada. Para
produção, o projeto está preparado para PostgreSQL (tem config no SETUP.md).
■ O que é Bean Validation?
■ Um conjunto de anotações (@NotBlank, @Email, etc.) que valida dados automaticamente quando você
coloca @Valid no parâmetro do Controller.
■ O que é JaCoCo?
■ Plugin Maven que analisa quais linhas de código foram executadas durante os testes e gera um
relatório de cobertura em porcentagem.
